# douyin-fav — 项目背景(给设计/前端)

所有 UI spec 的共享上下文。设计任何界面前先读这份。

## 这是什么

一个**本地自托管**的小工具:把你**抖音收藏夹**里的视频转成**文字稿**,自动同步进你的 **Notion**。
有字幕的视频直接取字幕,没有的用本地语音识别(whisper)把口播转成文字。

## 解决什么问题 / 谁用

用户在抖音收藏了很多「干货」视频,想把里面的口播/字幕变成**可搜索、可归档**的文字,沉淀到 Notion 知识库。
用户在**自己电脑**上跑(Mac / Windows / Linux 桌面),半技术(会用命令行跑 `npm`,但希望日常操作在网页点)。

## 端到端流程

```
装依赖 → 扫码登录抖音 → 连 Notion → 配收藏夹
   ↓(之后服务自动,每小时)
扫收藏夹 → 找出新视频 → 转写(字幕轨 / whisper ASR)→ 写一页进 Notion
```

## 架构(直接影响 UI 决策)

- 一个**常驻本地 Node 服务**,在 `localhost` 上发出几个网页。
- **真正干活的是服务**:用 Playwright 开浏览器抓抖音、whisper 本地转写、Notion REST 写入。**网页只是调服务 API 的薄壳**。
- 因此两条铁律:
  1. **网页碰不到文件/命令/扫码**。凡涉及这些的,都由服务在宿主机执行——例如**扫码登录是宿主机弹出的 Chrome 窗口完成的,不在网页里**;网页只负责发起 + 轮询状态。
  2. **重活是分钟级**(语音识别),所以是**异步任务 + 轮询**模型,不是同步等待。

## 几个界面(都在 localhost,**视觉风格必须统一**)

| 界面 | 作用 | spec |
|---|---|---|
| `/` | **单条字幕提取**:贴链接直接拿这一条的文字稿(不写 Notion) | `transcribe-ui-spec.md` |
| `/setup` | 首次安装向导(检测依赖→登录→连 Notion→开同步) | `setup-wizard-ui-spec.md` |
| token 管理 | 抖音登录账号池(扫码加、验证、轮换) | `token-admin-ui-spec.md` |
| `/config` | 配置(收藏夹/Notion/调度)+ 同步控制面板 | `config-ui-spec.md` |

**拿文字稿有两条独立的路**,设计时别混:
1. **即取即得(`/`)** — 用户主动贴一条链接,网页里直接看结果,不碰 Notion。最面向用户。
2. **自动同步(`/config` 控)** — 服务后台定时扫收藏夹,批量写进 Notion。

## 关键约束(塑造 UI 的)

- **单浏览器、单账号、串行排队**;一条 ASR 要几分钟 → 任何「处理中」都要有明确 loading/进度,别让用户以为卡死。
- 跑在用户**自己的抖音账号**上 → 涉及平台 ToS/风控,**文案别鼓励高频滥用**,失效要能提示重新登录。
- **本地优先 / 隐私**:登录态(cookies)只存本机档案目录,Notion token 存本机配置文件,**不上传任何云**。这是卖点,可在 UI 体现。
- **无既有品牌/视觉规范** → 设计可自由定调,但上面几个页面要成一套。

## 术语表(设计者可能不熟)

- **抖音** = 中国版 TikTok。**收藏夹** = 用户收藏的视频合集(可有多个)。
- **token**(本项目语境)= 一次扫码登录的浏览器档案,**不是 API key**;池子可放多个,自动轮换 + 失效转移。
- **字幕轨 vs ASR**:部分视频自带字幕,直接取;没有的用 whisper 本地把口播识别成文字。
- **Notion integration token + databaseId**:用户在 notion.so/my-integrations 建的内部集成密钥 + 目标数据库 id。

## 语气

中文界面。定位是**自用的运维 / onboarding 工具**:清晰、可信 > 花哨。深色模式加分。
